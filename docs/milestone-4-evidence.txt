Submit shows the exact six-column schema, row rules and file/record/cell limits, plus the previously planned valid/invalid sample downloads. Operators select one file; viewers see a read-only explanation. Durable success appears only after the API response. A new import and an identical-byte duplicate have different messages; the returned server state is shown without assuming processing started. Structural errors map safe API codes to actionable guidance, associated with the file control. Unknown upload outcomes instruct identical-file resubmission to recover the existing import.

History uses the owner-scoped API, newest first, with filename, submitted time, text state, completed counts and cursor pagination. Loading, empty, unavailable and error states are explicit. Details show run/attempt, state and timestamps, safe failure summaries, counts, paginated rejected-row explanations and authorized downloads. Retry is shown only for an API-confirmed operator when canRetry is true; the UI sends expectedRun:1 and refetches durable state rather than incrementing counters locally.

Details use a dedicated polling hook: one request at a time, three-second scheduling, no hidden-document timer, no terminal polling, abort on departure, and blocked polling for session/403/404 errors. Temporary fetch failure preserves the last confirmed document and displays “Status unavailable; last updated …”. Elapsed time never implies queue outage, worker failure or percentage progress.

Browser authentication uses keycloak-js 26.2.4 with the existing public odi-web client, Authorization Code + PKCE S256, provider redirect, adapter-managed state/nonce, memory-only access/refresh tokens and provider-session recovery on reload. No client secret or localStorage token persistence is introduced. The only application sessionStorage value is a validated same-origin return path. API calls use the adapter's access token, never its ID token. The UI derives role from /v1/me and does not display the subject.

Accessibility includes native controls, associated labels/descriptions, visible keyboard focus, skip navigation, route-change heading focus, semantic table headers/caption, text status labels, plain-text rejected values and restrained announcements. No uploaded HTML is interpreted. Protected downloads use authorized fetch and a short-lived blob URL; raw exceptions, JWTs and Mongo/internal fields are not rendered.

7. LEARNING NOTES

React state should reflect the last confirmed server snapshot, not manufacture processing transitions. Separating the polling hook from rendering makes visibility, cancellation, terminal states and stale-response handling easier to review. Re-fetching after mutations/reload recovers the durable result without duplicating business state in the browser.

OIDC browser integration requires care at the redirect boundary: exact registered origins/callbacks, PKCE, adapter-managed state/nonce, memory-only tokens, access-token refresh, and a validated return path. Provider-session recovery allows reload without persisting tokens. UI role gates improve usability; the API still decides authorization.

Accessibility combines semantics and interaction: associated errors, a sensible focus destination after navigation, keyboard activation of native controls, named table regions, non-color status text, and announcements that change only when useful. Automated scans and headless browser tests provide useful evidence while leaving explicit platform/assistive-technology limits.
