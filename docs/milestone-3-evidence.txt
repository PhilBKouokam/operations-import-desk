1. IMPLEMENTED BEHAVIOR

Frozen v1.1 processing/recovery only. No React UI or excluded product features were added.

MongoDB owns durable input, state, attempts, schedules, leases and results. A dispatcher atomically reserves a due PENDING import using database time and advances nextDispatchAt by 30 seconds before enqueueing. Five-second scans reserve at most 100 imports. Dispatch does not consume processing attempts. Stable per-import/run BullMQ IDs, immediate completed/failed job removal, disabled producer offline buffering and a two-second enqueue deadline keep Redis a notification transport. The existing dispatch/expired-lease indexes remain unchanged and are verified at startup.

A conditional Mongo claim issues a random 60-second lease and increments one attempt. Validation yields every 100 rows and enforces a 30-second deadline. Publication/failure writes match import ID, run, PROCESSING state, current lease token and an unexpired database-time lease. Expired-lease recovery shares the three-attempt/run budget; transient retries wait two then four seconds. Only one authorized manual retry may create run 2. Repeated expectedRun:1 requests return the current second run without starting another run.

One Mongo update publishes the terminal state, complete result/counts, timestamps and event together. Business-invalid rows produce COMPLETED_WITH_ERRORS, including all-invalid files; they do not retry. BSON sizing includes the input/result/document and an 8-KiB conservative metadata reserve below the four-MiB ceiling. Oversized results fail nonretryably with no partial result. Failure messages and structured logs use explicit safe fields; logs exclude identity, tokens, lease tokens and raw rows.

Owner-scoped errors pagination, accepted/error CSV downloads and operator-only retry extend the existing NestJS API. Downloads quote/escape all cells and prefix spreadsheet-active values with an apostrophe without modifying stored input. Empty categories produce header-only CSV. HTTP responses remain explicit allowlists. List queries omit full result rows as well as input bytes and lease tokens. Fault injection exists only in the local test harness, not public routes.

7. LEARNING NOTES

Redis/BullMQ job locks and acknowledgements solve transport problems; they cannot replace durable business intent. Stable IDs bound queued notifications, while Mongo nextDispatchAt bounds how often dispatch is attempted. Auto-removal matters because a completed transport no-op must not suppress future durable work.

A lease is not just a timestamp: publication must atomically match run, token, state and database-time validity. Expiry must fence a worker even before the recovery scanner notices it. Retry budgets belong beside those durable transitions, not in queue retry counters.

A failed response is not proof that a database write failed. Keeping the bounded whole result in one document makes both outcomes safe: either it remains recoverable without results, or it is already terminal with the full result. Fenced follow-up failure writes cannot undo the committed outcome.

The tests also exposed the difference between a business lease deadline and BullMQ's stalled-job detection cadence, and the need to preserve cross-chunk duplicate detection while yielding the event loop. These are implementation learning notes, not claims of independent mastery or professional NestJS/Redis/OIDC experience.
