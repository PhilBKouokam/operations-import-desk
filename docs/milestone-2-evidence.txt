1. IMPLEMENTED BEHAVIOR

NestJS 11.2.6 API with exact issuer/audience/algorithm validation via jose 6.2.12, Keycloak discovery/JWKS, required claims, 30-second clock tolerance and explicit access-token type check. Operator/viewer mapping is restricted to the configured API client. All import routes are authenticated and owner-scoped; operator-only upload is enforced before reading/persisting input.

MongoDB 7.7.0 Node driver targets a real MongoDB 8.0.15 server. Startup creates/verifies the unique owner+schema+content-hash index, owner-history index, approved nextDispatchAt index and expired-lease index. Index conflict prevents serving HTTP. One atomic pipeline upsert uses database time and preserves the entire existing document on duplicate. SHA-256 covers exact input bytes; majority+journal acknowledgement is requested.

Uploads require one CSV file part, no extra fields/files; file <=256 KiB, entire envelope <=272 KiB, including chunked requests. Fatal UTF-8 and structural CSV validation occur before persistence. MIME/filename and encoding checks, a ten-second upload timeout, bounded buffering and ten uploads per minute per verified subject/IP are implemented. Filenames are display-only and stripped of paths/control characters.

List/detail use explicit response allowlists, owner filters, stable cursor pagination and safe error envelopes. Missing/foreign imports produce equivalent 404 codes/messages. Private owner identity, inputBytes, leaseToken, contentHash, nextDispatchAt, JWTs and internal errors are absent from import responses. GET /v1/me intentionally returns only the caller's subject and role, as specified.

Health endpoints report liveness/MongoDB readiness. CORS is restricted to the configured origin; security/cache headers are set. Required configuration and discovery failures stop startup. No product OIDC login screen/browser session handling is implemented in M2.

No Redis/BullMQ worker, dispatcher, recovery execution, retry endpoint, CSV export/result publication or UI was added. Every accepted import remains PENDING. nextDispatchAt is stored/indexed but not dispatched.

6. LEARNING NOTES

NestJS: authentication guards run before controller work; request parsing can be deliberately restricted instead of accepting a generic body parser. Typed providers/module boundaries keep token verification, input parsing and persistence separate. Exception filters must return explicit safe envelopes rather than raw errors.

MongoDB: concurrent request correctness depends on the database unique index and atomic upsert, not a check-then-insert in application code. Pipeline updates need $literal for user-controlled values and $$NOW for database-owned timestamps. Explicit response DTOs prevent BSON/private fields from leaking. Native real-server tests exposed integration behavior that unit assertions cannot establish.

OIDC/Keycloak: ID tokens and API access tokens have different purposes. Signature validity alone is insufficient: issuer, audience, expiry, access-token type and intended client roles all matter. Keycloak scopes/mappers can add audience claims; negative fixtures must verify their own assumptions. PKCE-enabled code flow worked against a real identity provider without a product UI or password grants.
